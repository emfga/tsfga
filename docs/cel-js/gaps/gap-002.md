# GAP-002 — both engines accept, the readings differ

**Direction: silent.** Both store the model, both answer the
check, the answers differ, and nothing errors anywhere. The
JavaScript reading was the wider or the empty one in every
measured case — usually the empty one, so the symptom is access
disappearing with no error to search for.

Seven constructs: `\A`, `\Q…\E`, `\s`, the POSIX class family
(`[[:alnum:]]`, `[[:alpha:]]`, …), `\p{L}` and `\pL`. Table:
[`../regex/re2-vs-celjs.md`](../regex/re2-vs-celjs.md), group 2.

The concrete shape, measured: `[[:alnum:]]+` against `"abc123"` is
true in RE2 and **false** in JavaScript, while the same pattern
against the literal `"[:alnum:]"` is false in RE2 and **true** in
JavaScript. JavaScript reads the POSIX class as a character class
of the seven literal characters `[ : a l n u m`.

**This is the group that killed the deny-list.** A scanner built
from RE2's grammar refuses what RE2 refuses; RE2 *accepts* every
construct here, so all seven pass straight through it.

**Closed in tsfga by dropping `matches()`.**

**A fork must** make `matches` *read* patterns as RE2 does. This
is not a translation problem — there is no rewriting of `\s` that
gives it RE2's member set in a JavaScript engine — so it is the
group that makes the fix engine-shaped.
