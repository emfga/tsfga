# GAP-006 — `double('1e-400')`, closed in tsfga's favour

A divergence the compatibility layer **created** rather than
closed, and the retirement removes it.

cel-go's `double(string)` takes the underflow: OpenFGA v1.18.2
answers `true` for `double('1e-400') == 0.0`. tsfga's owned
`tsfga_double` overload refused it — `double() type error: value
out of range` — and the comment above `DOUBLE_ZERO` in
`conditions.ts` asserted the opposite, that upstream reports a
range error.

So one of the emulations was itself a **refusing** divergence,
against a claim about upstream that the container does not
support. Deleting the overload closes it.

A small row, recorded because of what it illustrates: an emulation
written to track another engine's behaviour is only as good as the
last time somebody measured that behaviour, and nothing in the
build would have told anyone it had drifted.
