# GAP-005 — the magnitude family

**Direction: granting.** cel-go range-checks a conversion and
cel-js does not, so tsfga answers where OpenFGA raises.

| expression | OpenFGA | cel-js |
|---|---|---|
| `int(1e100)` | check error: integer overflow | answers |
| `int(-1e100)` | check error: integer overflow | answers |
| `double('1e400')` | check error: type conversion error | answers |
| `double('-1e400')` | check error: type conversion error | answers |

**Both ends of every two-sided check**, which an earlier ledger
lost by listing only the positive ends.

tsfga used to close this with owned `tsfga_int` / `tsfga_double`
overloads reached through the source splicer. Those are the
emulation the retirement removes, so the family is now shipped as
a pinned divergence instead.

It joins an already-open family rather than opening a new one:
`cel-operators.test.ts` pins six unchecked-operator cells of
identical shape, structurally unclosable because cel-js's
`registerOperator` refuses to replace a built-in.
