# GAP-007 — conversions cel-go declares and cel-js does not

**Direction: refusing.** Five overloads, all at check time:
`int(uint)`, `int(duration)`, `int(timestamp)`,
`string(duration)`, `string(timestamp)`. OpenFGA answers; cel-js
has no such overload and raises at evaluation.

These are **per-branch**, because cel-js short-circuits:
`int(d) > 3600 || role == 'admin'` still answers `true` when the
right arm holds, on bare cel-js and on OpenFGA alike.

They are check-time rather than write-time only because the
write-time type gate is narrowed to ignore cel-js's
`found no matching overload for` verdicts. Without that narrowing
they would be write-time refusals, which is strictly worse: a
model upstream stores would not load at all.

tsfga used to close these with owned overloads plus the source
splicer. That is the emulation the retirement removes.
