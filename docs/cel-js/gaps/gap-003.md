# GAP-003 — RE2 accepts, JavaScript rejects

**Direction: refusing.** `new RegExp` throws, so tsfga cannot
answer where upstream answers. An outage, not a leak.

Two families: the leading inline flag group `(?i)`, `(?m)`, `(?s)`
and Python-style named groups `(?P<name>…)`. Both are accepted by
OpenFGA v1.18.2 and raise `SyntaxError: Invalid regular
expression: unrecognized` in cel-js 8.0.0.

This is the only group a pure syntax translation closes, and the
retired translator did close it — see
[`../retired/translate-re2-pattern.ts.txt`](../retired/translate-re2-pattern.ts.txt),
`LEADING_FLAGS` and `FLAG_GROUP`. Closing it was correct and was
never the problem; the problem was that closing it required a
source splicer and left GAP-001 and GAP-002 open.

**Closed in tsfga by dropping `matches()`**, in the sense that the
expression no longer stores at all.
